# H700 Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Itch-io on the Anbernic RG XX (Allwinner H700) family as `nextui/h700`, without regressing any device that works today.

**Architecture:** H700 is one NextUI platform (`PLATFORM=h700`) spanning eleven SKUs distinguished by `$DEVICE`. It reuses the existing portable `nextui/tg5040` binary via a copy row in `scripts/targets.sh` — no new toolchain, no new compile, no second binary in the Pak Store zip. The real work is in four places: a screen-size predicate that stops treating 720-wide panels as roomy, a third face-button arrangement, `$DEVICE`-derived device identity, and a `launch.sh` library search order that finds NextUI's own SDL2 instead of stock Anbernic's.

**Tech Stack:** Go 1.22, CGo + SDL2 (`veandco/go-sdl2` v0.4.40), POSIX `sh` launchers, containerised cross-compile (podman/docker), shell-based structural tests.

**Design doc:** `docs/superpowers/specs/2026-08-16-h700-support-design.md`

## Global Constraints

- **Nobody owns H700 hardware.** Every H700 claim here is derived from upstream source, not measured. Do not "verify" an H700 behaviour by asserting it — verify it by making it visible in the log.
- **`nextui/h700` is a copy target, never a compile.** Row: `nextui:h700:tg5040:no:nextui/tg5040:2.17`.
- **The pak ships no SDL2 for H700.** No `lib/h700/` may appear in any artifact.
- **`go build -tags headless` does not compile `screen_*.go` or `input.go`** (they are `//go:build !headless`). CI green does not mean the device build compiles. Any task touching those files must run `./scripts/build.sh native` before commit.
- **No colour literals in drawing code** — `scripts/no-color-literals.sh` rejects numeric RGB triples. No task here should add colours; if you do, take them from `internal/theme`.
- **All new/modified code carries structured `internal/logger` calls.** No `fmt.Println` / `log.Printf` in production paths.
- **Screenshot output goes to `/tmp/itchio-screenshots/`**, never `docs/screenshots/`.
- **Commit trailer** on every commit: `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`
- **Branch:** `feature/h700-support`. Do not merge to `dev` until Task 8 passes.

// is where a two-branch if/else stops being honest about what varies.
var faceArrangements = map[firmware.FaceMapping]faceArrangement{
	firmware.FaceSwapped: {

		sdl.CONTROLLER_BUTTON_Y, sdl.CONTROLLER_BUTTON_X,

		sdl.CONTROLLER_BUTTON_Y, sdl.CONTROLLER_BUTTON_X,
	},

// SetFaceMapping points the face-button bindings at the given arrangement.
// Called once at startup, before any screen handles an event.
func SetFaceMapping(m firmware.FaceMapping) {

    # Only targets that ship their own SDL2 get a lib dir.  h700 links the

        mkdir -p "$PLAT_PAK/lib/$dev"
        cp -L "$(toolchain_libdir "$(target_toolchain "$t")")"/* "$PLAT_PAK/lib/$dev/" 2>/dev/null || true
    fi
done

- [ ] **Step 1: Audit the new geometries**

In `scripts/palette-audit.sh`, replace the single `go run` invocation and its result handling with a loop over geometries:

```sh
# Geometries every shipping device actually presents.  1024x768 is the TrimUI
# Brick; 640x480 is the Miyoo Flip and most of the H700 family; 720x480 is the
# RG34XX line and 720x720 is the RG Cube XX.  The last two are new with H700 and
# are the reason the size class stopped keying on width alone — rendering them
# here is what makes that change something we looked at rather than reasoned
# about.
GEOMETRIES="1024x768 640x480 720x480 720x720"

STATUS=0
for geom in $GEOMETRIES; do
    W="${geom%x*}"
    H="${geom#*x}"
    # shellcheck disable=SC2086
    if go run ./cmd/devshot --all --palettes all --width "$W" --height "$H" \
        --out-dir "$OUT_DIR/$geom" --audit $EXTRA >"$log" 2>&1; then
        summary="$(grep -E 'finding\(s\)' "$log" | sed 's/^ *//')"
        # Count renders only; --sheet adds one "contact sheet:" line per scene.
        renders="$(grep -cE '^    [a-z].*\.png ' "$log")"
        printf 'ok   - palette audit %s: %s renders, %s\n' "$geom" "$renders" "${summary:-no findings}"
    else
        printf 'FAIL - palette audit %s found unreadable text:\n' "$geom"
        grep -E '^\s+FAIL' "$log" | sed 's/^ */  /'
        printf '  (renders in %s/%s)\n' "$OUT_DIR" "$geom"
        STATUS=1
    fi
done

exit "$STATUS"
```

## Notes for the implementer

**Two build tags, two meanings.** `go test -tags headless` is fast and needs no SDL2, but it does not compile `screen_*.go`, `input.go`, or `main_sdl.go`. Tasks 1, 2 and 3 all touch files excluded from that build. `./scripts/build.sh native` is the check that matters; `./scripts/test.sh` runs both.

**Test ordering.** Tasks 1-4 are independent of each other and can be done in any order. Task 5 must precede Task 6. Task 7 depends on Task 1 (it renders what Task 1 changed). Task 8 depends on everything.

**When something contradicts this plan, the device wins, then the spec, then the plan.** Every H700 fact here is derived from upstream source. If a tester's log disagrees with any of it, the log is right.
