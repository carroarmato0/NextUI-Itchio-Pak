## Itch-io v1.1.0

The biggest release so far. You sign in with your phone instead of typing an API
key, paid games are shown to everyone, the app copes with flaky Wi-Fi, and it
now tells you about its own updates — and on NextUI installs them for you, with
an automatic rollback if one does not start. Tested through rc1–rc4 and on
hardware.

### Before you update

- **You will be asked to sign in once.** API keys are no longer used: on the
  first start the old key is removed from your settings. Your installed games,
  paid ones included, stay where they are, and you can still play, delete and
  rename them without signing in. Only downloading paid games needs it.
- Settings, sign-in and your downloaded-games list are kept, on NextUI and muOS.

### Sign in with your phone

Settings → Account shows a QR code. Scan it, approve on itch.io, and check the
code on the handheld matches. No more typing an API key on a D-pad.
Settings → Account shows who is signed in; **Y** signs out.
See [Signing in](https://github.com/carroarmato0/NextUI-Itchio-Pak/blob/main/docs/sign-in.md).

### Paid games, for everyone

- Paid games are listed whether or not you are signed in. Their page says what
  **A** will do: sign in to download, download a game you own, or scan the QR
  code to buy it on itch.io.
- A game you downloaded while it was free that has since become paid says so —
  *You have a free copy — buy it on itch.io to update*.
- Game details (prices, suggested amounts) come from itch.io's per-game data
  feed, so they are more reliable and each page needs one request fewer.

### App updates

- **A small notice** slides in at the top right once per new version, and
  **Settings → App updates** shows the details, a manual **Check now**, and the
  release page as a QR code.
- **Channels:** Stable, Release candidates, or Off. If you run a release
  candidate you are kept on release candidates, so you hear about the final
  release and the next test build. Only a newer version is ever offered.
- **NextUI, Pak Store:** when the Store will offer the update, Itch-io points you
  to it and never installs around it. If the Store is about to offer a version
  *older* than the release candidate you run, the Updates screen warns you.
- **NextUI, everything else** (a release candidate, or an install the Store does
  not manage): **Install** downloads the update, verifies its size and checksum,
  unpacks it beside the app and checks it again before anything is replaced.
  **Restart now**, or install it the next time you open Itch-io. **B** cancels a
  download and leaves nothing behind.
- **If an update does not start**, the previous version is put back
  automatically, a warning bubble says so once, and the Updates screen offers
  **Retry**. If the Pak Store or a manual copy replaces Itch-io after an update
  was downloaded but before it was installed, the download is discarded rather
  than installed over your choice.
- **muOS:** **Save to ARCHIVE** downloads and verifies the update and leaves it
  for **Applications → Archive Manager**.

In-place install arrives with this version, so it is used from the next update
on: moving to 1.1.0 itself still goes through the Pak Store or a manual install.

### When the Wi-Fi drops

- The game list stays usable from the cache. An **Offline** chip says why
  nothing new arrives, covers show *Offline*, and the list, covers, inventory
  check and update check pick up by themselves when the connection is back — no
  relaunch, and no endless retrying in the meantime.
- Connection problems are explained in plain words: no Wi-Fi, itch.io having
  problems, a Wi-Fi sign-in page, or a wrong date and time.
- A game page that cannot load still shows the title, tags, QR code and, for
  downloaded games, the files and **Delete** — so you can manage games offline.
- Downloads go to a hidden partial file and only replace a game once complete.
  A dropped connection, crash or power cut no longer damages the copy you have;
  leftovers are cleaned up at the next start.

### Game updates

- Signed in, update checks use itch.io's API instead of starting a download per
  game. That also catches a re-uploaded file with the same name, and covers paid
  games.
- The game page and the file picker say which file an update is.

### Settings

Settings is grouped into **Account, Downloads, Library, Appearance and App**,
with each value shown on the right. **L1/R1** jump between sections, and the
list wraps from bottom to top.

### Devices

- **Anbernic H700 on NextUI h700-rc11 and later:** A and B are the right way
  round. rc11 changed how H700 numbers its buttons; Itch-io now reads the
  controller's full ID to tell the new layout from the old one, and older NextUI
  releases keep working as before. Thanks to the NextUI H700 maintainer for
  tracking down the last piece (#5).

### Fixes

- Updating a game packed in a ZIP no longer loses the copy you have if
  extraction fails.
- A ZIP with a README.md inside no longer counts the README as a Mega Drive
  game, so the file picker offers the actual ROM.
- Filter & Search: **Y** clears the filters, as the footer says.
- Price and *Downloaded* labels are easier to read on light palettes.
- Game pages with long descriptions use much less CPU while open.
- The GBA feed is requested directly.
- A dropped connection while sending a request is now recognised as being
  offline, like other connection drops.
